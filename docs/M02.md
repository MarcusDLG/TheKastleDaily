## Database operations

| Login | Responsibility |
| --- | --- |
| `kastle_bootstrap` | Initialize the PostgreSQL cluster and run the one-shot provisioner |
| `kastle_migrator` | Own the newspaper schema, manage the source registry and run Alembic |
| `kastle_app` | Read the source registry, update feed cache validators and persist workflow data with explicit grants |

The API uses a bounded SQLAlchemy connection pool. `/healthz` checks
process liveness and `/readyz` checks that the runtime login can read the
migrated edition table. The API responds with a generic 503 when that
query fails. Only the one-shot services receive the credentials they need.

Follow the local startup commands in the [README](../README.md).
Provisioning is repeatable and applies the passwords in `.env` to the two
M02 roles. To rotate the runtime password, update `.env`, rerun
`docker compose run --rm provision`, then recreate the API using
`docker compose up -d --force-recreate api`. The PostgreSQL bootstrap
password is set when the volume is initialized. Changing the value in
`.env` alone does not rotate that role.

For an existing M00 volume, verify PostgreSQL 17, SCRAM authentication,
checksums and the original bootstrap login before using the startup
sequence. The provisioner adds roles and the newspaper schema to the
existing database. Compose initialization flags apply when creating a new
volume. Preserve the existing volume during upgrades and take an
appropriate backup before changing a database containing data.

Use `docker compose run --rm migrate alembic current` to inspect the revision
and `docker compose run --rm migrate alembic check` to compare the migrated
schema with the models. The first revision's downgrade to base drops every
M02 table and its data. The acceptance script exercises that downgrade
against a disposable volume.

Ingestion will normalize canonical URLs and external IDs before writing.
The scheduler will derive the local edition date from the editorial
timezone. The delivery worker will claim outbox entries transactionally,
apply retry policy and route ambiguous results to review. M02 provides
the keys and state needed for those later workflows.
